# Sesión 2026-08-21 — Skill `ameyao-deploy` reescrita al formato real del servidor + regeneración del deploy de traspasos

Proyecto de simulación de traspasos VCC/PUSER (módulo PHP del servidor AMEyAO). ## 1. Verdad de terreno del formato AMEyAO (carpeta EJEMPLO)

### Problema
La skill `ameyao-deploy` asumía un modelo de conexión rígido (`db_meyg()` + `db_oraread()` con credenciales fijas) y decía que los archivos raíz del servidor "no se copian". El doc de migración, en cambio, empujaba a inyectar `principal.php`/`footer.php` en cada página. No estaba claro cuál reflejaba la realidad.

### Solución
El `EJEMPLO SERVIDOR` resolvió las dudas:
- **Dos niveles de `conexion.php` conviven a propósito.** La raíz del servidor (`index_principal_conexiones/`) tiene `conexion.php` con `db()`→meyg + helpers de sesión (`e()`, `require_login()`, `current_user()`) y `session.php` mínimo. Cada **módulo** trae su **propio** `conexion.php` con las conexiones de datos que necesite.
- **El módulo es autocontenido:** incluye su `conexion.php` + `helpers.php` + CSS y se dibuja solo; **NO** inyecta `principal/footer` por página. El puente de vuelta es un enlace "← Principal" a `../principal.php`. → La skill acertaba al seguir esto; el doc de migración (regla 6) NO aplica a AMEyAO.
- **Cross-db por calificación SÍ se usa:** `db_meyg()` llega a `qv_server.retim_eventos` calificando la tabla (visto en `01_listado.php`). Solo se abre otra conexión cuando el usuario/host es genuinamente distinto (oraread).

## 2. `conexion.php` real de traspasos: 4 conexiones, no 2

### Problema
Confirmar cuántas conexiones usa la app de traspasos para saber si la skill (que hardcodeaba 2) le servía.

### Solución
`codigo_php/conexion.php` (idéntico al del deploy) declara **4 conexiones**, mismo host `ewaahicdca00`, **2 usuarios**:

| Función | Base | Usuario |
|---|---|---|
| `db()` | meyg | OperAnalisys |
| `db_retim()` | qv_server | **user_nmt** |
| `db_agui()` | inf_tecnica_agui | OperAnalisys |
| `db_tlc()` | telecontrol_systems | OperAnalisys |

Además usa el patrón **`config.php` + fallback hardcodeado** (`file_exists(config.php) ? require : [...]`): en dev el `config.php` gitignoreado trae credenciales; en deploy no viaja y caen los valores hardcodeados. Esto **invalidaba** el paso 4 original de la skill (que decía "reemplaza config por hardcodeado"). Las 3 conexiones de OperAnalisys podrían colapsarse a una sola con tablas calificadas; solo `db_retim()` (user_nmt) necesita vivir aparte — optimización opcional, no aplicada.

## 3. Reescritura de la skill `ameyao-deploy`

### Problema
La skill no soportaba N conexiones, no reflejaba el formato auto-ejecutable que quiere el usuario (paquete = módulo + archivos raíz del servidor), no bundleaba documentación, y tenía una contradicción interna (ignorar vs commitear el deploy).

### Solución
Reescritura completa. Cambios clave:
- **Formato de paquete nuevo:** `AMEyAO_{Modulo}/` contiene el módulo **más** los 5 archivos raíz del servidor (`conexion/session/principal/footer/index`) copiados desde una **carpeta de archivos raíz** (default `index_principal_conexiones/`), para que el paquete corra local como el servidor.
- **Paso de conexión generalizado:** detecta N funciones `db_*()`, verifica que exista el **fallback hardcodeado** y que `config.php` no viaje al deploy (sí `config.example.php`); NO impone nombres ni credenciales fijas.
- **`_DOCUMENTACION/` dentro del módulo:** copia `DOCUMENTACION*.md`, `CHECKLIST*`, notas y las 2-3 `SESION_*` recientes (busca en la fuente y en la raíz del proyecto).
- **Verificación de endpoints de descarga:** CSV/JSON con `display_errors=0`, sin HTML antes de headers, `fputcsv/fgetcsv` con `escape` explícito.
- **Edición de `principal.php` del paquete:** inserta el `<li>` del módulo (auto-ejecutable + referencia exacta del cambio en servidor).
- **Commit condicional (fix de contradicción):** el deploy suele estar gitignoreado y sin trackear (artefacto local, no git). El paso 9 ahora detecta `git check-ignore`/`git ls-files` y **no fuerza commit** si es artefacto; solo commitea si el proyecto ya versiona el deploy.
